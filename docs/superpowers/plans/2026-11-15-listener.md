# Listener Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** An inviting accessible player for the existing live ambient stream.
**Architecture:** Buildless static page, native audio controller and optional isolated Caddy static/stream proxy.
**Tech Stack:** HTML/CSS/JavaScript ES modules, Node built-in tests, Caddy Docker.
**Spec:** `docs/superpowers/specs/2026-11-15-listener-design.md`

## Global Constraints

No autoplay, account, external font/asset/API, fake metadata/meter or Docker privileges. Four core services/data untouched. Optional local web only binds127.0.0.1:8080. Non-root/read-only. Three retries after1/3/8s, connection deadline15s, reset budget after30s stable playback. No hosted publication until actual target is known. Native execution under standing autonomy with one independent final review.

## Review Focus

- Pause/cancel and old promise/event completion must never resume unintended audio.
- A short connection that immediately drops must not reset bounded recovery forever.
- Error, stalled/buffering and browser permission rejection need distinct truthful states.
- Volume-uncontrollable mobile platforms need honest device-volume fallback.
- Proxy must expose the audio mount and static files only, not Icecast admin/status or station secrets.
